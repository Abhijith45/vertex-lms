# Implementation Prompt: Fix Sanity Session Error and Dataset Configuration

## 1. Goal
Eliminate the `Unauthorized - Session not found` (or `project user not found`) console error on localhost, correct the dataset setting in environment files from the non-existent `"development"` to `"production"`, strengthen `sanityFetch` in `web/sanity/lib/client.ts` to seamlessly fall back to public unauthenticated reads without throwing errors to server components, and restart the Next.js dev server to reload the environment.

---

## 2. Root Cause Analysis
1. **Dataset Not Found**: In `web/.env.local` and `studio/.env.local`, the dataset was set to `"development"`. Sanity API returns:
   `404: Dataset "development" not found for project ID "lb09hkdy"`. The existing dataset in this project is `"production"`.
2. **Token Project Mismatch**: `SANITY_API_READ_TOKEN` was generated by user `g-YXb3BWf7KdFH` who is not a member of project `lb09hkdy`, resulting in `401 Unauthorized (project user not found)`.
3. **Turbopack Dev Server State**: The active dev server needed to reload after file and environment updates, and `console.error` in Server Components was triggering Next.js's dev error modal.

---

## 3. Implementation Steps
1. **Update Environment Files**:
   - Set `NEXT_PUBLIC_SANITY_DATASET="production"` in `web/.env.local`.
   - Set `SANITY_STUDIO_DATASET="production"` in `studio/.env.local`.
2. **Enhance `web/sanity/lib/client.ts`**:
   - In `sanityFetch`, catch any 401/404 token authentication errors and transparently execute `client.fetch()` without throwing to the caller.
   - Ensure public dataset queries succeed without requiring an authenticated token.
3. **Restart Development Server**:
   - Restart `next dev` so Turbopack picks up the updated `.env.local` and clean module graph.
4. **Verify**:
   - Test `GET http://localhost:3000` to confirm 200 OK and no console error modal.
